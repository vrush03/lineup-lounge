# AGENTS.md

Lineup Lounge is a set of cricket games (Lineup: daily ranking; Ballpark: daily estimates; Showdown: stat cards against the computer; Who Am I?: name the player from a stat card): a React 19 + TypeScript + Vite single-page app
with no backend. All state lives in the browser's `localStorage`. See `README.md` for the game
and the data sources.

## Commands

```bash
npm install
npm run dev      # http://localhost:5173
npm run lint     # oxlint
npm test         # vitest: scoring logic + validation of every puzzle in the dataset
npm run build    # tsc -b && vite build
```

Run lint, test and build before calling a change done; CI (`.github/workflows/ci.yml`) runs the
same three, as separate `lint`, `test` and `build` jobs, on every PR and on `main`. Node version is pinned in `.nvmrc`.

## Layout

- `src/App.tsx`: the shell. Hash routes (`#lineup`, `#ballpark`, `#showdown`, `#whoami`, none = home), header, per-mode stats.
- `src/components/`: UI. `Home.tsx` is the mode catalogue; each mode has a `*Mode.tsx` container
  (daily/practice tabs) and a round component: `Game.tsx` for Lineup (drag to order, submit,
  marks), `Ballpark.tsx` for Ballpark (one number guess per question via `AnswerInput.tsx`,
  log-scale reveal; practice plays a random other day) with `RoundParts.tsx` (progress bar, points
  badge, round summary) and `roundStyles.ts`. Showdown has no daily:
  `ShowdownMode.tsx` is the format picker, `Showdown.tsx` the table, `PlayerCard.tsx` the card.
  Who Am I? is `WhoAmIMode.tsx` (daily, and practice by format), `WhoAmI.tsx` (the round) and
  `PlayerSearch.tsx` (the type-ahead over one deck); it shows a `PlayerCard` with `mystery` set
  (no name or team, photo blurred).
- `src/lib/`: pure logic, kept free of React so it is easy to test.
  - `score.ts`: marks each row `correct` / `near` (one place off) / `wrong`.
  - `ballpark.ts`: estimate scoring by ratio (`100 * (1 - |log10(guess / answer)|)`, full marks
    within 5%), guess parsing, colour bands, the daily question pick, "2.4× too low" text.
  - `showdown.ts`: the card game: deal, round outcome, points (`ROUNDS` rounds of `POINTS`), the
    computer's pick, saved-game check.
  - `whoami.ts`: Who Am I?: the daily card, the chips comparing a guess with the answer (team, role,
    era, batting hand), how close that is, which of the card's four hints are showing, how blurred
    the photo is (it clears with warm and close guesses and with the last hint), the commentary
    lines, name search, saved-round check.
  - `daily.ts`: maps the local calendar date to a puzzle index.
  - `storage.ts`: every `localStorage` read and write goes through here.
  - `puzzleSchema.ts` (zod) and `types.ts`: the puzzle shape.
- `src/data/cricket.json`: the generated puzzle set, loaded as its own lazy chunk.
- `src/data/ballpark.json`: Ballpark questions, generated by `scripts/data/gen_ballpark.py` from
  `scripts/data/ballpark_manual.json` (hand-written, sourced), sums worked out in the script, and
  Cricsheet totals. Each has a `family` (`scale`, `career`, `records`, `time`, `crowds`); a daily is
  five consecutive questions with at most two of a family, out of 500.
- `src/data/cards.json`: Showdown decks (one per format: ODI, T20I, Test, IPL), generated by
  `scripts/data/gen_cards.py` from the player lists in `scripts/data/cards_players.json`. International
  stats come from Wikipedia infoboxes, IPL from Cricsheet. Every stat is higher-wins.
- `src/data/whoami.json`: what Who Am I? adds to the Showdown cards, generated by
  `scripts/data/gen_whoami.py` from `cards.json`, the cached Wikipedia pages and Cricsheet: each
  player's role, batting hand and first and last year in each format they have a card for, four hints
  per card in the player's own voice (written by `scripts/data/whoami_hints.py`: how they play, debut
  and a highlight, team-mates including one from a different team, then nickname, birthplace and
  team), and the order each deck's cards come up as the daily. Stats are not copied: they are read from `cards.json` by card id.
- `scripts/data/`: Python pipeline (`common.py` holds what the question generators share) that builds `cricket.json` from raw downloads in `data-raw/`
  (git-ignored).

## Things to know before changing code

- **Never hand-edit `src/data/cricket.json`, `src/data/ballpark.json`, `src/data/cards.json` or `src/data/whoami.json`.** Change the generators in `scripts/data/` and rebuild
  (steps in `README.md`). `build.py` rejects ties, duplicate labels, already-solved puzzles and
  initials-only names; fix names in `scripts/data/name_overrides.json`.
- **The daily puzzle is `dayNumber % puzzles.length`.** Adding, removing or reordering puzzles
  changes which puzzle every future (and the current) day shows. Treat dataset changes as
  releases, not tweaks. `puzzles.test.ts` also enforces that puzzles sharing a prompt are at least
  30 days apart in the rotation. Ballpark is the same idea: `dailyQuestions` takes
  five consecutive questions starting at `day * 5`, and `gen_ballpark.py` orders them into those
  days, so any change reshuffles future daily rounds. Keep it to whole days of five, at most two
  questions of a family and at most one IPL question a day (the tests check).
- **Re-run `gen_whoami.py` after `gen_cards.py` whenever the player lists change.** The tests fail if
  a card has no bio or a deck and its daily order differ. The Who Am I? daily is the deck
  `SHOWDOWN_FORMATS[day % 4]` and that deck's order at `floor(day / 4)`, so adding or removing a
  player reshuffles future days; the generator keeps anyone from being the answer twice in 14 days.
  A role missing from an infobox, or a nickname to swap or drop, goes in
  `scripts/data/whoami_overrides.json`, checked against the page.
- **Who Am I? hints are derived, never hand-written.** `whoami_hints.py` only quotes an international
  match count when Cricsheet has the player's whole career in that format, and a best innings only
  when it equals the highest score on the card; keep new hint kinds to the same standard. The first
  three hints must not contain the player's name (the generator and the tests check).
- **Hand-written Ballpark facts must be sourced.** Check every number and claim in
  `ballpark_manual.json` (prompt, working and fact) against the linked page or Statsguru before adding it;
  don't rely on memory. IPL questions should derive their numbers from the data, with
  an assert for anything the wording takes for granted.
- **Saved games are player data.** Daily Lineup saves are keyed `game:cricket:<day>:<puzzleId>`
  with stats in `stats`. If you change a saved shape, make `storage.ts` discard or migrate old
  values instead of crashing (see how `loadGame` rejects old boolean marks).
- Daily Ballpark saves are `ballpark:cricket:<day>` (the question ids and one guess each) with
  stats in `stats:ballpark`; `loadBallparkStats` keeps the old three-bucket counts from when a round
  was out of 300. Quiz was removed; its old `quiz:*` and `stats:quiz` keys are simply ignored.
- Showdown saves a game in progress as `showdown:<format>` and its record in `stats:showdown`.
  `isGame` in `showdown.ts` throws away a save whose cards are no longer in the deck, so removing a
  player from a deck is safe.
- Daily Who Am I? saves are `whoami:cricket:<day>` (the card id and the ids guessed) with stats in
  `stats:whoami`, the same shape as Lineup's. `isRound` in `whoami.ts` throws away a save for a
  different card or with a guess that is no longer in the deck.
- Player photos live in `public/players/<name-in-lower-case-with-hyphens>.jpg`, with each file's source
  in `scripts/data/player_photos.json`. `gen_cards.py` only gives a card a `photo` when the file
  exists, so re-run it after adding or removing photos; cards without one show initials on the team colour.
- Wrap any new storage access in the existing `read` / `write` helpers; storage can be unavailable
  and the game must still work.
- Team logos live in `public/logos/ipl/`; the tests fail if a referenced logo file is missing.

## Style

- TypeScript strict-ish (`noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax`): use
  `import type` for type-only imports.
- No semicolons, single quotes, 2-space indent. Match the surrounding code.
- Styling is Tailwind CSS v4 utility classes; there is no component library.
- Keep game logic in `src/lib/` with tests next to it (`*.test.ts`).

## Deploys and dependencies

- Vercel deploys production from `main` only; other branches do not deploy (`vercel.json`).
  Don't add preview-deploy workflows or change that file without being asked.
- Dependabot opens weekly PRs for npm and GitHub Actions (`.github/dependabot.yml`).
- `main` is protected: changes from anyone else go through a PR that needs 1 approval and passing
  `lint`, `test` and `build` checks. The owner (vrush03) can bypass this and push straight to `main`;
  the owner prefers that, so only use a branch and PR when explicitly asked. Merged branches are
  deleted automatically.
